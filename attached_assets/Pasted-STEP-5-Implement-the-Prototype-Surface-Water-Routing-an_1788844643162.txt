STEP 5 — Implement the Prototype Surface-Water Routing and Accumulation Model

Now build the next modeling layer using the successfully generated runoff outputs.

IMPORTANT:
This is still a transparent research/prototype model, NOT an engineering-grade hydrodynamic or hydraulic model.

Do not fabricate pipe capacities, pipe diameters, invert elevations, Manning coefficients, measured water levels, blockage percentages, or other GHMC/HMWSSB hydraulic measurements.

The objective of this step is:

RUNOFF → TERRAIN-BASED SURFACE WATER MOVEMENT → WATER ACCUMULATION

Do NOT implement safe routing yet.

Do NOT claim the resulting values are measured flood depths.

==================================================
1. INPUT DATA
==================================================

Use the existing validated/preprocessed datasets and outputs:

- outputs/model/runoff/runoff_depth_mm.tif
- outputs/model/runoff/runoff_volume_m3.tif
- processed DEM
- processed GHMC Nalas
- processed tanks/water bodies
- GHMC boundary

Do not modify the original source datasets.

==================================================
2. GRID ALIGNMENT
==================================================

Use the existing DEM grid as the modeling grid.

Validate and explicitly handle:

- CRS
- width/height
- transform
- pixel size
- extent
- nodata

Ensure runoff and DEM are aligned.

Do not silently resample without documenting the method.

==================================================
3. TERRAIN DERIVATION
==================================================

From the DEM derive:

- elevation
- slope
- flow direction
- basic drainage/flow accumulation information

Use a transparent terrain-routing method suitable for a prototype.

A D8-style flow-direction approach is acceptable.

For each valid cell, determine the neighboring lower/equal-elevation cell toward which surface water can preferentially move.

Avoid creating flow paths outside the GHMC boundary.

Document limitations of the terrain-routing approach.

==================================================
4. SURFACE WATER ACCUMULATION
==================================================

Use the runoff volume as the incoming water source.

Implement a reproducible terrain-based accumulation model.

At minimum:

1. Start with runoff volume generated in each valid cell.
2. Route a configurable fraction of the water toward downstream terrain cells.
3. Accumulate incoming water from upstream cells.
4. Convert accumulated volume into an equivalent surface-water depth using cell area.

The model must be deterministic and reproducible.

Do not generate random flood depths.

==================================================
5. DRAINAGE / NALA INTERACTION
==================================================

Use the actual GHMC nala geometries already processed.

Snap/intersect nala geometry with the modeling grid where appropriate.

Identify cells that intersect or are sufficiently close to a nala.

However:

DO NOT assign real hydraulic capacities because those measurements are unavailable.

Instead implement a clearly labeled configurable prototype drainage-assumption layer.

For example, allow parameters such as:

- drainage_capture_fraction
- drainage_effectiveness
- maximum prototype drainage removal

These must be explicitly labeled:

"prototype_assumption"

and stored in configuration rather than hard-coded.

Do not present these values as measured GHMC drainage capacities.

==================================================
6. WATER BODIES
==================================================

Use the processed tank/water-body polygons.

Identify grid cells intersecting water bodies.

Do not treat water-body cells as ordinary urban surface cells.

Document how water bodies are handled in the prototype.

Do not invent actual tank storage levels, spillway capacities, or operating rules.
